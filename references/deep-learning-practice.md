# 深度学习实验设计黄金标准（基于 Goodfellow《深度学习》第11章）

Goodfellow, Bengio, Courville 的《Deep Learning》第11章"Practical Methodology"是所有深度学习实验的权威标准，也是NeurIPS/ICLR/CVPR等顶会审稿人的默认参考框架。

---

## 🎯 深度学习项目的标准流程（Goodfellow 推荐）

### 第一步：选择性能度量（Performance Metrics）

> **核心观点：** "90%的初学者错误，根源在第一步就选错了评估指标。"

#### ✅ 按任务类型的标准指标集

| 任务类型 | 必须报告的指标 | 不能只报告 |
|---------|--------------|-----------|
| **分类任务** | 准确率、精确率、召回率、F1、ROC-AUC、PR-AUC、混淆矩阵 | 只报告准确率 |
| **目标检测** | mAP@0.5, mAP@0.75, mAP@[0.5:0.95], 速度(FPS), 参数量 | 只报告mAP@0.5 |
| **分割任务** | mIoU, Dice系数, HD95(豪斯多夫距离), 边界IoU | 只报告mIoU |
| **生成图像** | FID, IS, 人类评估(至少10人), 消融 | 只报告FID |
| **NLP生成** | BLEU, ROUGE, BLEURT, 人类评估 | 只报告BLEU |

#### ❌ 经典错误
1. **指标单一化：** "我的准确率95%"但召回率只有50%（把所有样本都预测为多数类）
2. **用训练集指标：** 在训练集上测性能，然后报告"准确率很高"
3. **指标选择错误：** 用准确率评估严重不平衡的数据集

---

### 第二步：建立合理的基准（Baselines）

> **Goodfellow 核心观点：** "在你证明你的方法比所有合理的基线都好之前，你的方法什么都不是。"

#### ✅ 基线的层次（从易到难，缺一不可）

| 基线层次 | 内容 | 目的 | 没有的后果 |
|---------|------|------|----------|
| **L1 常识基线** | 随机猜测、多数类猜测、最简单规则 | 证明你的任务不是白给的 | "连随机都不如，你做了个啥？" |
| **L2 经典方法** | 传统机器学习方法（SVM, LR, RF） | 证明深度学习是必要的 | "你的深度模型还不如SVM，有意义吗？" |
| **L3 标准架构基线** | 最常用的标准架构（如ResNet50, BERT-base） | 证明你的改进不是架构本身带来的 | "你只是用了更大的模型而已" |
| **L4 近年SOTA** | 过去1-2年的最好方法 | 证明你真的有进步 | "你的方法还不如3年前的，有啥贡献？" |

#### ❌ 审稿人一眼识破的作弊手段
1. **基线不公平：** 自己的方法训1000epoch，基线只训100epoch
2. **基线不调参：** 自己的方法仔细调参，基线用默认参数
3. **精心挑选：** 只在你的方法表现好的数据集上做实验，回避不好的
4. **过时基线：** 只跟5年前的方法比，不跟最近1-2年的比

> **顶会标准：** 至少要有5-8个基线，覆盖L1-L4所有层次

---

### 第三步：默认的基准模型架构

> **Goodfellow 核心观点：** "一开始不要做花里胡哨的东西。先用最标准的架构把问题跑通，确认问题是可解的，然后再改进。"

#### ✅ 各领域的默认基准架构
| 领域 | 默认基准 | 不要一开始就用 |
|------|---------|--------------|
| 计算机视觉 | ResNet-50 | 你自己设计的100层怪东西 |
| NLP | BERT-base | 你自己预训练的小模型 |
| 强化学习 | PPO | 你自己发明的新算法 |
| 语音 | Wav2Vec 2.0 | 你自己的新架构 |

#### ❌ 常见错误
- 一开始就做了10个创新点，结果根本不work，不知道是哪个创新点没用
- 没有先跑通基准，直接上自己的方法，最后发现基准都比你好

---

### 第四步：数据集划分的黄金标准

#### ✅ 正确的划分流程（必须严格遵守）
```
原始数据
   ↓
1. 先打乱（必须随机种子固定）
   ↓
2. 按比例切分：训练(70-80%) / 验证(10-15%) / 测试(10-15%)
   ↓
3. 所有模型在训练集上训练，在验证集上调参
   ↓
4. 最终结果只在测试集上报一次，而且只能报一次
```

#### ❌ 红线（任何一个出现直接拒稿）
1. **数据泄露：** 测试集出现在训练过程中（哪怕只是看一眼Loss）
2. **在测试集上调参：** "我发现这个参数在测试集上更好"
3. **测试集用多次：** 在测试集上测了10个模型，然后报最好的那个
4. **不打乱：** 按时间顺序划分，前面训练后面测试，不打乱

> **Goodfellow 警告：** "如果你在测试集上做了任何决定，那你的测试集性能就是假的。"

---

### 第五步：超参数优化的规范

#### ✅ 标准流程
1. **先粗搜：** 宽范围，少轮次，找到大致区域
2. **再细搜：** 缩小范围，多轮次
3. **最后验证：** 最优参数在独立测试集上跑一次

#### ✅ 超参数搜索方法优先级
1. **随机搜索 > 网格搜索** （Goodfellow 强烈推荐随机搜索）
2. **贝叶斯优化 > 随机搜索** （但不要过度优化）
3. **不要用手工试错！** （90%的人还在这么干）

#### ❌ 常见错误
1. **搜索范围太小：** 学习率只试了1e-3, 2e-3, 5e-3，最优可能是1e-4
2. **搜索不充分：** 只试了5组参数就说"这是最好的"
3. **超参数泄露：** 用测试集性能来选超参数

---

### 第六步：处理过拟合和欠拟合的诊断流程

Goodfellow的诊断流程图：

```
训练误差很高吗？
   ├─ 是 → 欠拟合
   │    ├─ 增大模型
   │    ├─ 改进优化算法
   │    └─ 调正则化（减小）
   └─ 否 → 看验证误差
         ├─ 验证误差远大于训练误差 → 过拟合
         │    ├─ 更多数据
         │    ├─ 增强正则化（L2, Dropout, 数据增强）
         │    ├─ 早停
         │    └─ 减小模型容量
         └─ 两者都很低 → 完美
```

#### ❌ 常见错误
1. **过拟合就加数据：** 首先应该检查是不是数据泄露了
2. **盲目增大模型：** 小模型都训不好，大模型只会更糟
3. **只看验证误差：** 不看训练误差就不知道是过拟合还是欠拟合

## 🔬 消融实验的规范（Ablation Study）

> **Goodfellow 核心观点：** "消融实验是你证明'你的每个创新点都有用'的唯一方法。没有消融，你只是堆了一堆东西，没人知道哪个有用。"

### ✅ 标准消融实验的结构

```
完整方法 = 基础模型 + 创新点A + 创新点B + 技巧C

消融变体：
1. 基础模型（什么都不加） → 性能：X
2. 基础模型 + A → 性能：Y → A的贡献：Y-X
3. 基础模型 + B → 性能：Z → B的贡献：Z-X
4. 基础模型 + A + B → 性能：W → 交互效应：W - (Y+Z-X)
5. 完整方法（A+B+C） → 性能：V → C的贡献：V-W
```

### ✅ 消融实验的黄金标准
1. **每个声称的创新点都必须单独验证**
2. **必须验证模块之间的交互效应**（不是1+1=2那么简单）
3. **必须报告每个模块的参数数量和计算量**（不能是"更大的模型所以更好"）
4. **必须有误差棒和统计显著性检验**

### ❌ 不合格的消融
1. **只消融一个模块，其他模块都一起上**
2. **只说"加了A之后提升了2%"，不说A加了多少参数**
3. **没有交互效应分析**：不知道A和B是互补还是冗余

## 📊 深度学习实验的可复现性检查清单

这是顶会审稿人现在最看重的部分，很多顶会现在有"可复现性主席"专门查这个：

```
□ 代码开源了吗？（GitHub链接）
□ 预训练模型公开了吗？
□ 所有随机种子都报告了吗？（初始化、数据划分、打乱）
□ 框架版本和依赖包版本都列出来了吗？
□ GPU型号和数量都报告了吗？
□ 训练时间报告了吗？
□ 推理时间报告了吗？
□ 超参数完整列表提供了吗？
□ 数据集划分方式详细说明了吗？
□ 数据预处理/增强的完整流程说明了吗？
□ 优化器的所有参数都报告了吗？（学习率、衰减、动量等）
□ 早停的策略说明了吗？
```

## ⚠️ 深度学习10大经典错误（顶会审稿人零容忍）

| 排名 | 错误 | 严重程度 | 审稿人原话 |
|------|------|---------|-----------|
| 1 | 数据泄露，测试集参与训练/调参 | 🔴 直接拒 | "This is a fatal flaw. Results are meaningless." |
| 2 | 只报最好的一次运行结果，不报均值方差 | 🔴 直接拒 | "Cherry-picking. Results are not reliable." |
| 3 | 基线不公平，自己的方法比基线训得久/调得好 | 🔴 直接拒 | "Unfair comparison. Not acceptable." |
| 4 | 没有消融实验，不知道哪个模块有用 | 🟡 大修/拒 | "Without ablation, contribution is unclear." |
| 5 | 评估指标单一，只报最好看的那个 | 🟡 大修 | "Metrics are insufficient. Need to report X, Y, Z." |
| 6 | 没有统计显著性检验 | 🟡 大修 | "Is the improvement statistically significant?" |
| 7 | 没有误差棒/置信区间 | 🟡 大修 | "Please add error bars over multiple runs." |
| 8 | n<3，每个实验只跑1-2次 | 🟡 大修 | "Need at least 3-5 runs with different seeds." |
| 9 | 超参数搜索不充分，只试了几组 | 🟢 中修 | "Hyperparameter search is insufficient." |
| 10 | 可复现性信息缺失 | 🟢 中修 | "Please release code and specify all details." |

## 🎯 不同等级会议的实验标准对比

| 标准 | 普通会议 | CCF-B类 | CCF-A类 | 顶会(NeurIPS等) |
|------|---------|--------|--------|----------------|
| 基线数量 | 1-2个 | 3-5个 | 5-8个 | 8+个，覆盖所有相关SOTA |
| 运行次数 | n=1也可以 | n≥3 | n≥3-5 | n≥5-10，必须有方差 |
| 统计检验 | 不需要 | 最好有 | 必须有 | 必须有，还要效应量 |
| 消融实验 | 可有可无 | 最好有 | 必须有 | 必须有，还要有交互分析 |
| 可复现性 | 不用开源 | 最好开源 | 要求开源 | 强制开源，还要有复现指南 |
| 误差分析 | 不需要 | 最好有 | 必须有 | 必须有，还要有失败案例分析 |

## 💡 Goodfellow 的终极建议

> "如果你只能记住一件事，记住这个：**先做最简单的东西，把它做对，然后再一点点改进。**

> 90%的博士生一开始就想搞个大新闻，做了一个无比复杂的方法，结果根本不work，然后花了半年时间debug，最后发现问题出在一个弱智的bug上，或者其实最简单的基准方法就已经比他的好。

> 正确的流程是：
> 1. 先跑一个最简单的基线，确认它work
> 2. 然后每次只加一个改动，确认每个改动都带来提升
> 3. 最后才把所有有用的改动组合起来
>
> 这个过程虽然慢，但它保证你最后得到的是一个可靠的结论，而不是一堆乱七八糟的东西。"
